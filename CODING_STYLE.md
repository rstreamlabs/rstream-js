# Coding Style

Production code only. Type safety is strict: no any, no as, no untyped JSON, no silent coercions. Prefer narrow types and small pure helpers. Errors are explicit and meaningful: throw HTTPError with the right status and message, and avoid swallowing exceptions unless you have a clear fallback path. No let; use const, expressions, and small helper functions instead of reassignment. Functions contain no blank lines and no inline comments. Keep only section comments above exported functions to label responsibilities. Imports are one symbol per line: never destructure multiple imports from the same module on a single import line. Code should stay compact and readable: avoid defensive checks that the types already guarantee, avoid duplication, prefer single-pass logic, and keep IO calls minimal.
